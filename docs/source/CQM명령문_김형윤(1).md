# CQM 상품 제작 명령문 — 김형윤

> **이 파일의 목적**
> CODEX에게 Figma 기준 상품 HTML 제작을 요청할 때 사용하는 입력 템플릿이다.
> 매 작업마다 바뀌는 값은 **[변수 목록]**에, 실행할 내용은 **[명령문]**에 구분해 적는다.
> 상세 제작·검증 기준은 [CQM\_김형윤.md](./CQM_김형윤.md)를 따른다.

> **실행 시점**
> 문서를 열거나 정리하는 것만으로 HTML을 생성하지 않는다.
> Figma 링크와 작업 범위를 채운 뒤 작업 생성을 요청하면 지정 범위의 HTML을 바로 생성한다.

## 작업자 준비 순서

1. 상품 작업 폴더와 섹션 순서 / 이름을 정한다. `1 / 상품개요`를 입력하면 상품 작업 폴더 아래 `1.상품개요/`에 PC/MO 파일을 생성한다.
2. Figma MCP에서 읽을 수 있는 PC/MO 디자인 노드 링크를 준비한다. PC와 MO의 기본 구성은 각각 `일반`이다. 각 기기가 일반과 다를 때만 해당 구성 방식에 `tabs`, `accordion`, `tabs + accordion` 등을 입력한다. PC와 MO는 서로 다른 구성을 사용할 수 있다.
3. 전체 파일의 문맥도 필요하면 전체 참고용 Figma 링크를 선택 입력한다. 별도 PC/MO 에셋 링크는 기본 입력 항목으로 두지 않는다.
4. 디자인에 버튼이 있으면 통합 버튼 항목에 링크·동작을, GTM 항목에 영역별 태깅을 입력한다. 이미지 폴더명과 CDN 기준 경로도 확정된 값으로 입력한다.
5. 아래 변수 목록과 명령문을 함께 전달한다. VAR-09에 생성할 출력 폴더 범위를 지정한다.
6. 지정 범위의 PC/MO HTML 제작을 우선 진행한다. 이미지 업로드는 작업자가 별도로 진행하며, 검증·웹접근성 평가는 추후 사용자 요청 시에만 수행한다.

```text
■ 기본 진행 원칙
- 작업 생성·수정을 우선한다. 제작에 필요한 Figma 원본·로컬 에셋 확인과 접근성 구현은 진행한다.
- 사용자가 지정한 Figma 링크의 이미지·아이콘을 PNG로 다운로드하여 지정된 로컬 에셋 폴더에 저장하는 작업을 사전 허용한다. 제작에 필요한 재다운로드와 해당 에셋 갱신도 별도 확인 없이 진행한다.
- VAR-00·VAR-09로 확정된 작업 범위에서 생성된 pc.html·mo.html의 수정과 덮어쓰기를 사전 허용한다. 해당 범위의 후속 수정도 매번 승인을 요청하지 않고 진행한다.
- 기업/상품/cqm_작업내역.md의 작업 기록 추가·갱신을 사전 허용한다. 기존 기록을 유지하면서 별도 확인 없이 반영한다.
- 상시 사전 허용(항상 허용): 이 명령문의 VAR-00·VAR-09로 확정된 제작 범위에서 Figma 접속·PNG 다운로드, 다운로드 폴더 접근, 생성 스크립트 실행에 필요한 사용자 경로 읽기, 현재 작업공간의 HTML·이미지 다운로드 목록 생성, 지정된 lg.cqm/[VAR-00] 폴더의 결과물 저장·수정·덮어쓰기, cqm_작업내역.md 기록 추가·갱신을 항상 허용한다.
- "샌드박스가 Node의 사용자 폴더 접근을 막았습니다. 작성한 생성 스크립트를 실행해 현재 작업공간에 PC/MO HTML n개와 이미지 다운로드 목록을 생성하도록 허용할까요?"에 해당하는 작업은 위 범위에서 항상 사전 허용된 것으로 처리하고, 대화로 재확인하지 않는다.
- "작성한 HTML n개와 Figma PNG n개를 지정된 lg.cqm의 [VAR-00] 폴더에 저장하고 작업내역을 추가할까요?"에 해당하는 작업도 위 범위에서 항상 사전 허용된 것으로 처리한다. 확정된 생성 수량과 상품 폴더가 달라져도 해당 명령문에 지정한 범위 안에서는 매번 승인을 다시 묻지 않는다.
- 이 상시 허용은 작업 의사에 대한 사전 승인이다. 실행 환경이 강제하는 샌드박스·파일·네트워크 권한 승인은 유지한다. 도구에 저장된 승인 규칙이 적용되면 재사용하고, 적용되지 않으면 필요한 도구 권한 절차만 진행한다. 별도 검증 허용으로 확대하지 않는다.
- 위 허용은 사용자에게 작업 승인을 반복해서 묻지 않도록 하는 지침이다. 실행 환경이 강제하는 파일·네트워크 권한 승인은 이 문서로 해제하지 않으며, 필요한 경우 도구의 권한 절차를 따른다.
- 이미지 업로드는 작업자가 별도로 진행한다. CDN 업로드·응답 확인은 실행하지 않는다.
- 정적 검사·테스트·브라우저 실행·웹접근성 평가 등 별도 검증은 자동 수행하거나 승인을 요청하지 않는다. 추후 사용자가 요청한 범위만 검증한다.

■ 디자인 및 에셋
- 전체 문맥: [VAR-05]
- 실제 제작 기준: [VAR-06]의 기기별 디자인 노드
- 이미지·아이콘 출처: [VAR-06]의 각 디자인 노드에 포함된 에셋

- Figma MCP의 디자인 데이터와 스크린샷을 함께 확인한 뒤 제작한다.
- 문구·숫자·강조·배치·색상은 해당 노드 기준으로 작성한다.
- 색상값은 Figma 원본 그대로 출력한다. 예: #828282는 #828282로 유지하며, 웹접근성·명도 대비를 이유로 #616161 등 다른 색으로 임의 변경하지 않는다. 색상 변경은 사용자가 별도로 요청한 경우에만 적용한다.
- 기존 작업 결과, 다른 상품 소스, 이전 대화의 디자인·이미지 매핑을 재사용하지 않는다.

■ 상태별 Figma 프레임 연결
- 탭마다 별도 Figma 프레임 URL이 있으면 대상 기기·탭 그룹·탭 순서/이름·선택 상태 프레임 URL을 한 묶음으로 입력하고, 각 URL의 패널 내용을 해당 탭에 연결한다.
- 아코디언의 접힘과 펼침이 별도 프레임이면 대상 기기·그룹·항목별로 접힌 상태 프레임 URL과 펼친 상태 프레임 URL을 각각 입력한다. 같은 항목의 두 상태로 구현하며 별도 항목이나 섹션으로 생성하지 않는다.
- 섹션의 PC/MO 디자인 URL은 공통 배치·영역 위치의 기준이고, 상태별 URL은 해당 탭/항목의 상태와 상세 콘텐츠 기준이다. 상태 프레임에 전체 화면이 반복되어 있어도 공통 영역은 한 번만 작성한다.
- 상태별 프레임만으로 공통 배치까지 확인 가능하면 별도 대표 프레임을 필수로 요구하지 않는다. 확인할 수 없는 공통 영역이나 상태만 추가로 확인한다.
- 프레임 이름이나 URL 나열 순서만으로 상태를 추측하지 않는다. 기기·그룹·탭/항목·접힘/펼침 매핑을 기준으로 연결한다. 원본과 입력 매핑이 충돌하면 해당 부분만 확인한다.
- 탭 안에 아코디언이 있으면 소속 탭의 순서/이름 또는 ID를 함께 입력한다. 초기 활성 탭과 아코디언 초기 상태는 별도로 적용하며 URL 입력 순서로 결정하지 않는다.
- 프레임 수와 관계없이 각 섹션의 pc.html, mo.html 안에서 상태를 전환한다. 실제 클릭 기능과 ARIA·키보드 동작을 구현하며 프레임 이미지만 바꾸는 것으로 대신하지 않는다.

■ 구성 방식 및 공통 동작
- PC 구성 방식과 MO 구성 방식의 기본값은 각각 일반이다. 각 입력란이 비어 있으면 해당 기기만 일반 구성으로 제작한다.

- 아래 탭·아코디언 동작 규칙은 해당 유형을 입력한 기기에만 적용한다. 복수 유형은 각 그룹의 위치·소속·상태를 구분하고 필요한 기능만 구현한다.
- accordion이 포함되면 그룹별 접힘·펼침을 구현한다. button의 aria-expanded·aria-controls와 패널 hidden을 동기화하고, 기본 버튼의 Enter/Space 조작과 초점 표시를 유지한다.
- 아코디언은 여러 그룹·항목이 독립적으로 동작하도록 구현한다. '하나만 펼침'은 입력된 경우 해당 그룹 안에서만 적용한다. CMS 지연 삽입에 대응하는 이벤트 위임을 사용하고 중복 등록을 방지한다.
- 기타 유형은 제공된 디자인과 동작 설명을 기준으로 작성한다. 미제공 상세 콘텐츠·목적지·상태는 추측하지 않는다.
- 구성 방식에 tabs가 포함되면 [VAR-06]의 탭 그룹별로 각 탭과 대응 패널을 구현한다.
- 탭별 링크는 같은 화면의 전환 상태다. 화면 전체를 탭마다 중복 출력하지 말고 공통 영역은 한 번만 작성한다.
- 동일 섹션의 탭 그룹·패널은 해당 기기의 pc.html 또는 mo.html 안에 넣는다. 각 파일은 기기별 구성 방식과 원본에 따라 작성하며 탭별 하위 폴더나 HTML을 만들지 않는다.

- CQM_김형윤.md 7장의 data-cqm-tabs 구조와 공통 초기화·전환 규칙을 사용한다. 탭별 CSS는 각 Figma 디자인을 따른다.
- 여러 탭 그룹은 독립적으로 동작하게 하고, ID 충돌·이벤트 중복 등록을 방지한다.
- 클릭·키보드 전환, 초기 활성 상태, aria-selected·tabindex·hidden을 함께 처리한다.
- tablist·tab·tabpanel 역할과 이름, aria-controls·aria-labelledby 연결을 제공한다. Tab/Shift+Tab 진입·이탈, 방향키 초점 이동, Enter/Space 선택을 확인하고 초점 표시와 선택 표시를 구분한다. 비활성 패널은 읽기·키보드 탐색에서 제외한다.

- MO 규칙은 앞으로 생성하는 mo.html에 적용한다. 기존 파일은 기업/상품/U+MDR 하위 mo.html만 반영하며, 다른 상품의 기존 MO와 pc.html은 변경하지 않는다.

- style은 고정 복사본이 아니다. 기기별 Figma 디자인에 맞게 각각 작성한다.
- 필요한 상호작용이 있는 파일만 HTML 영역 뒤에 script를 추가한다.
```

- `/` 양쪽의 구분용 공백은 제거하고 섹션 이름 내부의 공백은 유지한다. 이름에 파일시스템에서 사용할 수 없는 문자가 있으면 임의 치환하지 말고 확인한다.
- `■ 번호. 섹션명`부터 그 섹션의 마지막 링크까지가 한 블록이다. 섹션이 여러 개이면 블록을 복사하여 빈 줄로 구분하고, 링크는 각각 독립된 줄에 붙여넣는다.
- 한 블록은 한 섹션과 그 출력 폴더를 뜻한다. 각 폴더 안에 `pc.html`, `mo.html`을 생성한다. 여러 섹션을 상품 루트의 한 파일로 합치지 않는다.
- 같은 순서 / 이름을 중복 입력하면 폴더가 충돌하므로 실행 전에 확인한다.
- PC와 MO의 디자인 링크는 각각 지정한다. 탭·아코디언은 기기별 상태 프레임 링크로 제공할 수 있으며, 공통 배치가 상태 프레임에 모두 포함되면 별도 대표 링크는 생략할 수 있다. 해당 섹션의 한쪽 기기 링크가 모두 비어 있으면 해당 기기 파일은 만들지 않고 누락으로 보고한다. 탭 일부만 누락된 경우는 아래 탭형 입력 규칙을 따른다.
- 별도 PC/MO 에셋 링크는 입력하지 않는다. 각 디자인 노드에 포함된 이미지·아이콘을 MCP로 확인하고 준비된 로컬 파일과 대조한다.
- 전체 파일의 문맥이 필요하면 VAR-05를 입력한다. 전체 링크는 선택이며 기기별 디자인 링크를 대신하지 않는다. 지정 노드에서 필요한 에셋을 확인할 수 없을 때만 해당 에셋의 위치나 추가 링크를 요청한다.
- PC 또는 MO를 탭·아코디언으로 구성할 때는 해당 기기·상태의 노드 링크와 소속 섹션을 함께 적는다. 일반 구성인 기기는 섹션의 디자인 링크를 사용한다.
- 블록에 입력하지 않은 폴더나 예전 상품의 탭 구성을 자동으로 추가하지 않는다.

### 구성 방식 입력 방법

- `PC 구성 방식`과 `MO 구성 방식`을 각각 선택 입력한다. 두 항목의 기본값은 모두 `일반`이며, 일반 구성이면 해당 입력란을 비워둔다.
- 일반과 다른 기기만 `tabs`, `accordion` 또는 기타 유형을 입력한다. 복합 화면은 `tabs + accordion`처럼 적는다.
- PC와 MO는 서로 독립적으로 구성한다. 예를 들어 PC는 `tabs`, MO는 `accordion`으로 입력할 수 있으며, 한쪽만 입력하면 다른 쪽은 일반 구성이다.
- 한 기기의 탭·접힘 상태·그룹 구조를 다른 기기에 자동 적용하지 않는다. 같은 유형이어도 각 기기의 원본과 상태별 링크를 따른다.
- `slider`, `modal` 등 다른 유형은 이름과 전환 방식·열기/닫기·초기 상태 등 필요한 동작을 함께 적는다. 유형 이름만으로 디자인에 없는 UI나 스크립트를 추가하지 않는다.
- PC/MO 디자인 링크는 구성 방식 입력 여부와 관계없이 기기별로 제공한다. 미입력된 구성 방식과 해당 기기 원본의 동작 구조가 명백히 충돌하면 해당 부분만 확인한다.

```text
PC 구성 방식 [선택, 일반과 다를 때만 입력] : tabs
MO 구성 방식 [선택, 일반과 다를 때만 입력] : accordion
```

위 값은 서로 다른 구성의 입력 예시이며 기본값이 아니다. 두 기기 모두 일반 구성이면 두 입력란을 모두 비워둔다.

### 아코디언 화면의 입력 방법

- 접고 펼치는 영역이 있는 기기의 구성 방식에 `accordion`을 입력한다. 탭 내부에 있으면 `tabs + accordion`으로 적고 소속 탭도 입력한다.
- 그룹별로 대상 기기, 초기 상태와 동시 펼침 허용 여부를 적는다. 미지정 시 초기 상태는 디자인을 따르고, 불명확하면 닫힘으로 작성한다. 여러 항목은 기본적으로 각각 독립적으로 열고 닫는다.
- 항목마다 접힌 상태와 펼친 상태의 Figma 프레임 URL을 구분해 입력한다. 각각 별도 프레임으로 제작되어 있으면 두 URL을 모두 입력한다. 하나의 프레임에서 두 상태를 확인할 수 있으면 같은 URL과 각 상태의 노드 위치를 적는다. 펼침 콘텐츠가 없으면 임의로 만들지 않는다.
- 그룹 전체의 접힘·펼침 화면을 각각 내보낸 프레임이어도 사용할 수 있다. 각 항목의 순서/제목과 프레임 안 위치를 적어 어떤 항목의 상태인지 연결한다. 동일 프레임 URL을 여러 항목에 사용할 수 있지만 전체 그룹을 항목마다 중복 출력하지 않는다.
- 다른 기기가 일반 구성이면 섹션의 디자인 링크만 사용하며 아코디언 항목별 링크를 요구하지 않는다. 다른 기기도 아코디언이면 해당 기기의 그룹과 링크를 별도로 입력한다.
- 다음 블록을 VAR-06의 해당 섹션 안에 추가한다. 탭과 함께 사용하는 경우 해당 기기의 소속 탭을 명시한다.

```text
▣ 아코디언 그룹 01
대상 기기 [필수, PC / MO 중 하나] :
아코디언 그룹 ID [accordion일 때 필수] : product-detail
소속 탭 / 위치 [선택] :
초기 상태 [선택, 닫힘 / 펼침 / Figma 기준] : 닫힘
동시 펼침 [선택, 허용 / 하나만] : 허용

• 항목 01
항목 순서 / 제목 [필수, 제목은 Figma 확인 가능] : 1 / Figma에서 확인
접힌 상태 Figma 프레임 URL [별도 프레임이 있으면 필수] :
펼친 상태 Figma 프레임 URL [필수, 상세 내용 포함] :
프레임 안 대상 항목 / 노드 위치 [그룹 전체 프레임이면 입력] :
```

### 탭형 화면의 입력 방법

- 같은 영역이 탭 선택에 따라 바뀌는 기기의 구성 방식에 `tabs`를 입력한다. 일반 구성인 기기의 입력란은 비워둔다.
- `▣ 탭 그룹`은 한 묶음의 탭 메뉴와 패널이다. 대상 기기를 명시하고, 한 기기에 탭 메뉴가 여러 개면 그룹 블록을 추가해 서로 다른 ID를 쓴다. 이 ID는 화면에 노출하지 않는다.
- `• 탭`은 그룹 내부의 한 선택 항목이다. 탭마다 해당 탭이 선택된 Figma 프레임 URL을 입력한다. 탭 1·탭 2·탭 3이 서로 다른 프레임이면 각 탭 블록에 각각의 URL을 넣는다. 실제 탭명은 입력하거나 `Figma에서 확인`으로 둔다.
- 각 프레임에서 탭 선택 표시와 해당 패널 내용을 확인한다. 모든 프레임에 반복된 제목·탭 메뉴·공통 본문은 한 번만 구현하고, 선택에 따라 달라지는 패널만 연결한다.
- 다른 기기가 일반 구성이면 섹션의 디자인 링크만 사용하며 탭마다 PC/MO 링크를 한 쌍으로 요구하지 않는다. 다른 기기도 탭형이면 해당 기기의 그룹과 링크를 별도로 입력한다.
- 서로 다른 그룹을 한 탭 메뉴로 합치지 않는다. 그룹의 위치는 해당 기기의 Figma 디자인을 따른다.
- 한 그룹의 초기 활성 탭을 지정할 수 있다. 미지정 시 Figma의 기본 상태를 따르고, 기본 상태가 불명확하면 첫 번째 탭을 선택한다.
- 링크가 여러 개라는 이유만으로 탭을 만들지 않는다. 탭 하나의 링크가 누락되면 다른 탭이나 다른 기기의 상태를 복제하지 않고 누락된 부분만 확인한다.
- 출력은 해당 섹션의 pc.html, mo.html 한 쌍이다. 각 기기의 구성 방식에 맞게 작성하며 탭 그룹 수와 탭 수에 따라 파일·폴더를 추가하지 않는다.

```text
▣ 탭 그룹 01
대상 기기 [필수, PC / MO 중 하나] :
탭 그룹 ID [tabs일 때 필수] : pricing-main
그룹 위치 [선택] :
초기 활성 탭 [선택, 미입력 시 Figma 기준] :

• 탭 01
탭 순서 / 이름 [필수, 이름은 Figma 확인 가능] : 1 / Figma에서 확인
선택 상태 Figma 프레임 URL [필수, 해당 탭의 패널 내용 포함] :
프레임 안 대상 탭 / 패널 위치 [여러 그룹이 있으면 입력] :

• 탭 02
탭 순서 / 이름 [필수, 이름은 Figma 확인 가능] : 2 / Figma에서 확인
선택 상태 Figma 프레임 URL [필수, 탭 02가 선택된 별도 프레임] :
프레임 안 대상 탭 / 패널 위치 [여러 그룹이 있으면 입력] :
```

### VAR-06 복사 샘플 — tabs / accordion

아래 샘플 중 필요한 구성을 VAR-06의 해당 섹션에 넣는다. `figmaUrl-*`는 실제 URL이 아닌 입력 자리 표시이며, 각 프레임의 Figma URL로 교체한다. 샘플의 탭명·항목명도 실제 디자인에 맞게 바꾼다. 두 샘플을 같은 섹션에 적용할 때는 섹션 머리말을 한 번만 쓰고 그룹 블록을 합친다.

**샘플 1: PC는 tabs, MO는 일반**

```text
■ 01. 상품개요
섹션 순서 / 이름 [필수] : 1 / 상품개요
PC 구성 방식 [선택, 일반과 다를 때만 입력] : tabs
MO 구성 방식 [선택, 일반과 다를 때만 입력] :

PC 디자인 [공통 배치 기준, 상태 프레임에 모두 포함되면 생략 가능] :
figmaUrl-pc-overview

MO 디자인 [MO 제작 시 필수] :
figmaUrl-mo-overview

▣ 탭 그룹 01
대상 기기 [필수, PC / MO 중 하나] : PC
탭 그룹 ID [tabs일 때 필수] : overview-tabs-pc
초기 활성 탭 [선택] : 1

• 탭 01
탭 순서 / 이름 : 1 / 탭 이름 01
선택 상태 Figma 프레임 URL :
figmaUrl-tab-01

• 탭 02
탭 순서 / 이름 : 2 / 탭 이름 02
선택 상태 Figma 프레임 URL :
figmaUrl-tab-02

• 탭 03
탭 순서 / 이름 : 3 / 탭 이름 03
선택 상태 Figma 프레임 URL :
figmaUrl-tab-03
```

`figmaUrl-tab-01`, `figmaUrl-tab-02`, `figmaUrl-tab-03`은 각각 해당 탭이 선택된 PC 프레임이다. MO가 탭형이면 `MO 구성 방식`에 `tabs`를 입력하고, 대상 기기를 `MO`로 바꾼 그룹에 MO 프레임 URL을 넣는다. 두 기기 모두 탭형이면 그룹을 기기별로 작성한다.

**샘플 2: PC는 일반, MO는 accordion**

```text
■ 01. 상품개요
섹션 순서 / 이름 [필수] : 1 / 상품개요
PC 구성 방식 [선택, 일반과 다를 때만 입력] :
MO 구성 방식 [선택, 일반과 다를 때만 입력] : accordion

PC 디자인 [PC 제작 시 필수] :
figmaUrl-pc-overview

MO 디자인 [공통 배치 기준, 상태 프레임에 모두 포함되면 생략 가능] :
figmaUrl-mo-overview

▣ 아코디언 그룹 01
대상 기기 [필수, PC / MO 중 하나] : MO
아코디언 그룹 ID [accordion일 때 필수] : overview-accordion-mo
소속 탭 / 위치 [선택] :
초기 상태 [선택] : 모두 접힘
동시 펼침 [선택, 허용 / 하나만] : 허용

• 항목 01
항목 순서 / 제목 : 1 / 항목 제목 01
접힌 상태 Figma 프레임 URL :
figmaUrl-accordion-01-closed
펼친 상태 Figma 프레임 URL :
figmaUrl-accordion-01-open

• 항목 02
항목 순서 / 제목 : 2 / 항목 제목 02
접힌 상태 Figma 프레임 URL :
figmaUrl-accordion-02-closed
펼친 상태 Figma 프레임 URL :
figmaUrl-accordion-02-open

• 항목 03
항목 순서 / 제목 : 3 / 항목 제목 03
접힌 상태 Figma 프레임 URL :
figmaUrl-accordion-03-closed
펼친 상태 Figma 프레임 URL :
figmaUrl-accordion-03-open
```

`closed`는 접힌 상태, `open`은 펼친 상태의 MO 프레임이다. 모두 접힌 화면이 프레임 하나이면 각 항목의 접힌 상태 URL에 같은 링크를 넣을 수 있다. PC가 아코디언이면 `PC 구성 방식`과 대상 기기를 바꾸고 PC 프레임 URL을 입력한다.

PC는 tabs이고 MO는 accordion인 경우 샘플 1의 PC 탭 그룹과 샘플 2의 MO 아코디언 그룹을 한 섹션에 함께 넣는다. 동일 기기의 탭 내부에 아코디언이 있으면 구성 방식에 `tabs + accordion`을 입력하고 아코디언의 `소속 탭 / 위치`를 명시한다.

### 버튼 입력과 GTM 태깅

- 상품보러가기·신청하기를 별도 변수로 두지 않고 VAR-01 하나로 관리한다. 화면의 버튼 유무·개수·배치는 Figma를 따른다. 입력란을 하나로 합치는 것은 디자인의 버튼을 임의로 삭제하라는 뜻이 아니다.
- VAR-01의 적용 위치는 선택이다. 비워두면 버튼 문구와 각 Figma의 실제 위치로 대상을 찾는다. 같은 문구·URL·동작의 버튼이 반복되면 해당 버튼에 모두 적용한다.
- URL·동작이 서로 다른 버튼은 VAR-01 안에 버튼별 블록을 추가하고 그룹·탭·영역으로 구분한다. 대상이 명확하지 않을 때만 확인한다. GTM 값은 위치가 추정되더라도 임의 생성하지 않는다.
- 디자인에 버튼이 없으면 VAR-01·07을 비운다. 링크나 태깅만 있다는 이유로 버튼을 만들지 않는다.
- 디자인 기준으로 버튼을 구현한 뒤, 해당 영역의 실제 클릭 요소인 `<a>` 또는 `<button>`에 확정된 `data-gtm-*` 속성을 붙여 HTML을 출력한다. 주변 래퍼나 내부 텍스트에 대신 붙이지 않는다.
- 아래는 사용자가 제공한 **U+SASE 태깅 샘플**이다. 현재 테스트AI샘플링의 확정 태깅이 아니며, 실제 적용할 값은 VAR-07에 입력한다. 샘플 상품명이나 속성을 자동 복사·치환하지 않는다.

```text
■ 상단배너 영역

data-gtm-event-name="button_click"
```

### 이미지 경로 입력 방법

- 최종 CDN 경로: `[VAR-02][VAR-03]/[실제 에셋 상대경로]`
- 예를 들어 CMS가 `biz/product/` 구조라면 VAR-02에 `https://www.lguplus.com/static/partners/cx/biz/product/`를 적는다.
- `pc/`, `mo/` 하위 경로는 실제 CMS 등록 구조에 있을 때만 포함한다. 파일명·확장자도 확인한 값을 사용한다.
- VAR-03 또는 VAR-02가 비어 있으면 로컬 상대경로를 사용한다. Figma 임시 URL을 최종 HTML 경로로 남기지 않는다.

### 현재 예시의 출력 위치와 이미지 경로

Figma PC/MO 디자인 링크를 입력하고 작업 생성을 요청하면 다음 위치에 바로 생성한다. 현재 문서 입력만으로 HTML을 생성하지 않는다.

```text
기업/상품/테스트AI샘플링/
  3.이용요금/               ← 3 / 이용요금 입력, 탭 패널 모두 포함
    pc.html                ← 생성할 PC 파일
    mo.html                ← 생성할 MO 파일
  87551/                   ← 준비된 이미지 폴더
    img_prod_1.png          ← PC 파일명 예시
    img_prod_m_1.png        ← MO 파일명 예시
    img_chk.png            ← 별도 아이콘; 용도는 Figma와 대조
```

- 현재 입력값의 CDN 경로는 `https://www.lguplus.com/static/partners/cx/biz/product/87551/` 뒤에 실제 파일명을 붙인다. 이미지 업로드는 작업자가 별도로 진행하며, 업로드·CDN 응답 확인은 기본 작업에서 제외한다.
- VAR-02를 비워 로컬 경로로 제작하면 섹션 폴더 안의 PC는 `../87551/img_prod_숫자.png`, MO는 `../87551/img_prod_m_숫자.png`를 사용한다.
- 별도 assets 폴더는 만들지 않는다. 제목의 dot은 CSS `::after`와 `content: '';`로 구현한다.
- 파일명을 새로 만들거나 번호를 다시 매기지 않는다. `img_chk.png`처럼 별도 이름의 파일도 실제 용도를 확인한 뒤 사용한다.
- PC/MO 디자인 링크는 위 입력값을 사용한다. 문서 정리 중에는 Figma 조회·HTML 생성·에셋 내보내기를 실행하지 않는다.

문서 구성만 블로그 명령문과 맞춘다. 블로그의 고정 CSS, 원본 HTML 변환 절차, 목차·CTA 규칙은 상품 제작에 적용하지 않는다.
