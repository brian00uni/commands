# 공통 작업 규칙 (CQM / 블로그 / GEO블로그 / 고객사례 / 뉴스레터 공통)

> 이 문서는 5개 콘텐츠 유형(CQM.md, 블로그.md, GEO블로그.md, 고객사례.md, 뉴스레터.md)에 동일하게 적용되는 규칙만 모아둔다.
> 콘텐츠 유형별 고유 규칙(클래스 체계, 섹션 구조, offset 값 등)은 각 가이드 문서에만 기술하고 여기에는 넣지 않는다.
> **명령문(프롬프트 템플릿) 파일에는 이 문서를 참조하지 않는다.** 명령문은 매 작업마다 변수값을 바꿔 붙여넣는 용도이므로, `@[가이드].md 지침을 준수하라`는 문구로 이미 이 공통규칙까지 간접 적용된다.

---

## 1. 환경 통제

- **터미널 실행 전면 금지:** 시스템 터미널(파워쉘, 배시 등)을 절대 열지 않는다. 보안 정책으로 통제되어 있으며, 오직 에디터 내부의 파일 읽기/쓰기 도구만 사용한다.
  - _예외:_ 뉴스레터 작업은 뉴스레터.md 8절의 허용 목록 범위에서만 터미널을 제한적으로 사용한다. 다른 콘텐츠 유형에는 적용하지 않는다.
- **파일 신규 생성/다운로드 최소화:** 외부 이미지 다운로드는 하지 않는다. 이미지 폴더 등 작업자가 미리 준비해둔 자산만 사용한다. (콘텐츠 본문 파일 자체를 신규 생성하는 것은 유형별 워크플로우에 따름 — 예: CQM/고객사례/GEO블로그는 새 pc.html/mo.html을 생성하지만, 뉴스레터는 기존 활성 파일만 수정한다.)

## 2. GTM 태깅 / Schema(ld+json) — 신규 생성 시 전면 제외

- **GTM 데이터 속성**(`data-gtm-event-name`, `data-gtm-event-category`, `data-gtm-event-action`, `data-gtm-event-label`, `data-gtm-click-location`, `data-gtm-click-text`)과 **`<script type="application/ld+json">` 스키마**는 신규 작업(새 페이지/탭/포스트 생성)에서 **다루지 않는다.** 입력란·예시 패턴도 만들지 않는다.
- 참고 소스(기존 상품/사례/블로그)에 이미 포함돼 있어도 그 값을 복사하지 않는다.
- 이 값들은 **총괄팀에서 별도로 받아 최종 입력하는 영역**이므로 Kiro의 작업 범위가 아니다. 신규 생성 워크플로우에는 관련 변수·placeholder를 두지 않는다.
- 예외: 사용자가 명시적으로 "GTM 붙여줘" 또는 "스키마 넣어줘"라고 요청한 경우에만 그 요청 범위 안에서 추가한다.

## 3. 접근성 공통 베이스

- **새창 링크:** `target="_blank"`인 모든 `<a>`/`<button>`에 `title="새창열림"` 필수.
- **버튼:** `type="button"` 명시.
- **테이블:** `caption` + `scope="col"` 필수 (행 헤더가 있으면 `scope="row"`도).
- **alt 기본 원칙:** 100자 이하는 `alt="텍스트"` 직접 기입, 100자 초과는 `alt=""` + `aria-describedby="imgN-desc"` + 인접 위치에 sr-only 블록으로 설명 이전.
  - 콘텐츠 유형별로 alt 판단 기준(이미지 안에 텍스트가 있는지, table/ul 마크업 보존 여부 등)이 다르므로 세부 규칙은 각 가이드 문서를 따른다.

## 4. 긴 본문 작성 시 청크 정책 (fs_write / fs_append 공통)

- **50줄 단위로 무조건 자르지 않는다.** 콘텐츠 유형별 논리적 섹션 경계(`geoSecN`, `content-section`, 탭 섹션 등— 각 가이드 문서 참고)를 기준으로 **100~150줄** 정도로 묶어서 작성한다.
- **체크포인트:** 섹션(청크) 하나를 추가할 때마다 `grep_search`로 그 섹션의 핵심 키워드(id, class, src 등)가 정상 삽입됐는지 가볍게 확인한다.
- **최상위 래퍼 마감 태그는 마지막 청크에서만 등장해야 한다.** `geo-post`/`article`/`st-main-content`/`st-entry-content` 같은 최상위 래퍼의 여는 태그는 첫 청크에서 한 번만 열고, 닫는 태그(`</div></div></article></div>` 등)는 푸터+스크립트를 포함한 **마지막 청크**에서만 등장해야 한다. 중간 섹션 사이에 래퍼 마감 태그를 넣으면 그 뒤 섹션이 래퍼 스타일(폭 제한 등) 밖으로 빠져나가 레이아웃이 깨진다. 청크를 추가할 때마다 `grep_search`로 해당 래퍼의 닫는 태그 패턴이 아직 등장하지 않았는지(마지막 청크 전까지 0건) 확인한다.
- 문제가 생기면 파일 전체가 아니라 **그 청크 범위 안에서만** 재작업한다.
- 목적: 호출 수를 줄이면서도 실수 발생 시 원인 범위를 좁게 유지하는 것. (50줄 제한 자체는 툴의 기술적 제약이 아니라 조기 발견을 위한 습관이었을 뿐이다.)

## 5. 진행상황 보고 규칙 (무응답/정지처럼 보이는 현상 방지)

- 도구 호출이 여러 번 연속으로 이어지는 작업(참고 폴더 다중 조회, 이미지 폴더 확인, 긴 본문 청크 작성 등) 중에는 중간중간 진행상황을 짧게(1~2문장) 텍스트로 보고한다. 텍스트 없이 도구 호출만 계속하면 작업이 멈춘 것처럼 보인다.
- **재확인(사용자에게 "맞습니까?", "계속할까요?" 묻는 것)은 실제로 판단이 필요한 분기점에서만 한다** — 예: 이미지 매핑이 불확실하거나 폴더 이미지 개수와 등장 횟수가 안 맞을 때, 참고 폴더가 여러 개라 구조가 상충할 때, 링크/문구를 확정할 근거가 없을 때. 단순 조회·확인 작업은 재확인 요청 없이 텍스트 보고만 하고 계속 진행한다.
- 여러 청크로 나눠 작성해야 하는 긴 작업을 시작하기 전에는 "N개 청크로 나눠서 진행합니다" 정도로 계획을 먼저 한 줄 알린다.

## 6. 에디터 자동 포맷팅으로 인한 마감 태그 중복 방지 (실제 발생 사례)

- **원인:** `.vscode/settings.json`의 `editor.formatOnSave`(Prettier 등 HTML 포맷터)가 켜진 상태에서 `fs_write`/`fs_append`로 태그가 아직 닫히지 않은 중간 상태의 HTML을 파일에 쓰면, 에디터가 저장 이벤트를 감지해 불완전한 태그 구조를 "정리"하려고 최상위 래퍼 마감 태그(`</div></div></article></div>`)를 자동으로 삽입하는 현상이 발견됐다(2026-08). 이 경우 `str_replace`로 지워도, 다음 저장 시점에 다시 삽입될 수 있다.
- **작업 시작 전 확인:** GEO블로그/블로그/고객사례처럼 `fs_write`(style만) → `fs_append`(본문, 여러 청크)로 긴 HTML을 청크 단위로 작성하는 작업을 시작하기 전에, `.vscode/settings.json`에서 HTML의 `editor.formatOnSave`가 켜져 있는지 확인한다.
- **켜져 있다면 작업 전 끄고, 작업 완료 후 반드시 원상복구한다 (기본 동작):**
  1. 작업 시작 전: `.vscode/settings.json`에서 HTML `editor.formatOnSave` 관련 값을 끄기 전에 **원래 값을 확인해서 기록**해 둔다(대개 `true`).
  2. 청크 작성 작업(fs_write style만 → fs_append 본문 여러 청크) 동안은 꺼진 상태로 유지한다.
  3. pc.html/mo.html 작성이 모두 끝나고 `get_diagnostics` + 태그 밸런스 검증(4장)까지 통과하면, **작업 완료 보고 전에 반드시 원래 값으로 복원**한다. 사용자는 평소 자동 포맷팅을 켜둔 채로 편집하길 원하므로, 끈 상태로 방치하지 않는다.
  4. 복원했다는 사실을 완료 보고에 한 줄로 언급한다(예: "editor.formatOnSave 설정 원복 완료").
- **청크 작성 중 이상 감지 시:** append 직후 파일 끝부분을 `read_file`로 확인했는데 아직 열려 있어야 할 태그가 이미 닫혀 있다면(예: 마지막 섹션이 아닌데 `</article></div>`가 보임), 포맷터가 개입한 것으로 의심하고 즉시 `editor.formatOnSave`를 끈 뒤 해당 마감 태그를 제거하고 이어서 진행한다.
