# CQM Figma 기반 상품 퍼블리싱 가이드 — 김형윤

> **적용 문서:** [CQM명령문\_김형윤.md](./CQM명령문_김형윤.md)
> 명령문에는 매 작업의 변수와 실행 범위를, 이 가이드에는 파일 포맷과 제작·검증 기준을 둔다.
> 이전 CQM 작업 결과나 작업 이력을 기준으로 삼지 않고, 이번에 제공된 Figma를 원본으로 제작한다.

## 1. 작업 목적과 범위

- CMS에 넣을 상품 콘텐츠를 출력 폴더별 `pc.html`, `mo.html`로 만든다.
- 작업 기준은 명령문의 VAR-06에 지정한 Figma 디자인 노드다. 에셋도 해당 디자인 노드에서 확인한다.
- **문서 정리 → Figma 링크·생성 범위 입력 → 지정 범위 HTML 생성·수정** 순서로 진행한다. 문서 정리 요청은 HTML 제작 요청으로 해석하지 않는다.
- 작업 생성 요청 시 별도 샘플 단계 없이 VAR-09에 지정된 출력 폴더의 제공된 PC/MO를 바로 생성한다. 입력하지 않은 출력 폴더로 작업을 확대하지 않는다.
- 이전 대화의 상품명·URL·요금·색상·클래스·이미지 매핑을 기본값으로 사용하지 않는다.
- 블로그 문서에서는 변수 목록과 명령문을 분리하는 구성만 참고한다. 블로그의 고정 style, 목차, 워드프레스 변환 방식은 적용하지 않는다.

### 규칙 적용

**기본 진행 원칙 — 작업 우선·요청 시 검증**

- 이미지 업로드는 작업자가 별도로 진행한다. 기본 작업에서 CDN 업로드·응답 확인을 실행하지 않는다.
- 정적 검사·자동 테스트·브라우저 실행·웹접근성 평가 등 별도 검증은 추후 사용자 요청 시에만 수행한다. 검증 실행을 위한 승인도 선제적으로 요청하지 않는다.
- Figma 디자인·에셋 확인과 접근성 마크업·대체 텍스트·키보드 동작 구현은 제작에 포함한다. 아래 확인·검사·평가 중 결과물 검증에 해당하는 절차는 별도 검증 요청 시에만 적용한다.
- 토큰을 최대한 절약한다. 필요한 부분만 읽고 중복 조회·불필요한 도구 호출·장황한 설명·전체 코드 재출력을 피한다. 작업 결과는 핵심만 짧게 기록한다.

1. 이번 작업에서 사용자가 명시한 범위와 추가 지시
2. 이번에 입력한 CQM명령문\_김형윤.md의 변수와 명령문
3. 이 가이드
4. [공통규칙.md](../공통규칙.md)의 공통 사항

- 공통규칙의 접근성·중복 방지·청크 작성 원칙을 적용한다.
- 이 워크플로우에서 지정된 Figma 원본 에셋의 내보내기와 출력 HTML 생성은 제작 범위에 포함한다. 공통규칙의 일반적인 외부 이미지 다운로드·신규 파일 제한과 구분한다.
- 기본 파일 작업은 에디터 읽기·편집 도구를 사용한다. 사용자에게 이미 허용받은 도구 사용 범위는 해당 세션에서 따른다.
- 사용자가 요청한 버튼 태깅은 VAR-07의 확정값으로 적용한다. 명령문에 있는 U+SASE 샘플은 작성 형식 참고용이며 기본값이 아니다. ld+json 스키마는 별도 명시 요청이 있을 때만 추가한다.

## 2. 입력값과 출력 파일 결정

### 입력 확인

- VAR-00 상품 작업 폴더, VAR-04 상품명, VAR-06 출력 목록, VAR-09 실행 범위를 확인한다.
- VAR-06의 각 세로 블록에서 섹션 순서 / 이름과 PC/MO 디자인 링크를 확인한다. 별도 출력 폴더명이나 PC/MO 에셋 링크는 입력받지 않는다.
- 구성 방식은 `일반`, `tabs`, `accordion`, 기타 유형 이름을 사용하며 `tabs + accordion`처럼 복수 입력할 수 있다. 고정된 선택 목록으로 제한하지 않는다. 미입력 시 디자인에서 구성을 확인하고 동작이 모호한 부분만 확인한다.
- `accordion`은 그룹 ID·항목 제목·펼친 내용의 PC/MO 노드·소속 탭·초기 상태·동시 펼침 정책으로 구분한다. 초기 상태는 디자인을 따르며 불명확하면 닫힘, 여러 항목은 기본 독립 동작으로 작성한다.
- 기타 유형은 이름과 동작 설명을 기준으로 필요한 기능만 작성한다. 유형 이름만으로 미제공 UI·콘텐츠를 추가하지 않는다.
- 구성 방식에 `tabs`가 포함되면 탭 그룹 ID·탭 순서 / 이름·기기별 상태 링크를 확인한다. 탭명이 `Figma에서 확인`이면 제작 시 원본 문구를 읽고 PC/MO의 대응 관계를 대조한다. 링크 나열 순서만으로 확정하지 않는다.
- VAR-01은 통합 버튼 입력, VAR-02는 이미지 CDN 기준 경로, VAR-07은 영역별 GTM 태깅이다.
- 작업 폴더는 입력 경로를 사용한다. 섹션 순서 / 이름은 `/` 양쪽의 구분용 공백을 제거하고 `[순서].[이름]`으로 연결한다. 섹션 이름 내부의 공백은 유지한다.
- 전체 참고용 링크(VAR-05)는 문맥 확인용이다. 출력 목록에 없는 영역까지 제작하지 않는다.
- 링크에 node-id가 없거나 대상 노드에 접근할 수 없으면 해당 노드를 요청한다. 확인하지 않은 노드를 추정하지 않는다.

### 출력 규칙

```text
[VAR-00]/
  [VAR-06의 순서.이름]/
    pc.html
    mo.html
```

- `new/`를 자동 생성하거나 폴더 이름을 정규화하지 않는다.
- `1 / 상품개요`는 `[VAR-00]/1.상품개요/pc.html`, `mo.html`로 출력한다. 각 섹션을 해당 폴더에 개별 생성하고 상품 루트에 합본 HTML을 만들지 않는다.
- 같은 순서 / 이름의 중복이나 파일시스템에서 사용할 수 없는 문자가 있으면 확인한다. 임의로 덮어쓰거나 이름을 치환하지 않는다.
- 섹션의 한쪽 기기 링크가 모두 없으면 제공된 기기만 제작한다. 탭 일부의 링크만 누락되면 다른 패널을 복제하지 말고 해당 누락과 처리 방향을 확인한다. PC를 축소하여 MO 원본인 것처럼 만들지 않는다.
- 같은 섹션의 탭 그룹·패널은 해당 폴더의 PC/MO 파일 안에 구현한다. 탭별 폴더·파일을 추가하지 않는다. 원본에서 반복되는 공통 머리말·탭 메뉴·공통 버튼은 실제 공통 영역인지 확인해 한 번만 작성한다.
- 원본에 없는 탭·섹션·내용을 출력 폴더명이나 기존 상품 구성만 보고 추가하지 않는다.
- 기존 출력 파일이 있으면 현재 요청이 수정·교체를 허용하는지 확인한다. 명시된 수정은 그 범위대로 처리하고, 덮어쓰기 의도가 불명확한 경우에만 확인한다.
- 읽어야 할 기존 파일은 변경 전 상태 확인용이다. 그 파일의 디자인을 새 제작의 근거로 사용하지 않는다.

## 3. PC/MO 공통 파일 포맷

### 형식 참고 범위

- 상품 폴더: `기업/상품/U+_지능형CCTV/`
- PC: `기업/상품/U+_지능형CCTV/1.상품개요/pc.html`
- MO: `기업/상품/U+_지능형CCTV/1.상품개요/mo.html`

위 파일에서는 **구분 주석, style 영역, contents 영역, 콘텐츠 래퍼**의 형식만 참고한다.
상품 문구, CSS 값, 이미지 주소, 기능, 탭 구성을 복사하지 않는다.
참고 MO에 있는 `-mt-40` 같은 보조 클래스도 기본값으로 붙이지 않는다.

### PC 골격

```html
<!-- PC : tab contents : [출력 영역명] -->
<style>
  /* 이 PC Figma 디자인에 필요한 CSS */
</style>

<!-- contents -->
<div class="cont-box-inner">
  <!-- [섹션명] -->
  <!-- 해당 PC 디자인의 본문 -->
  <!-- // [섹션명] -->
</div>
<!-- //PC : tab contents : [출력 영역명] -->
```

### MO 골격

```html
<!-- MO : tab contents : [출력 영역명] -->
<style>
  /* 이 MO Figma 디자인에 필요한 CSS */
</style>

<!-- contents -->
<div class="cont-box-inner">
  <!-- [섹션명] -->
  <!-- 해당 MO 디자인의 본문 -->
  <!-- // [섹션명] -->
</div>
<!-- //MO : tab contents : [출력 영역명] -->
```

### 구조 원칙

- 파일 앞의 기기·영역 주석 다음에 하나의 `<style>` 블록을 둔다.
- HTML 영역의 최상위 시작 태그는 **`<div class="cont-box-inner">`** 그대로 사용한다.
- PC는 `.cont-box-inner` 바로 아래 콘텐츠 래퍼(`div` 또는 `section`)의 해당 클래스 CSS에 **`margin: 0 auto 40px;`**를 기본 적용한다. 내부 이미지·표 등 하위 요소의 여백은 일괄 변경하지 않는다.
- 앞으로 생성하는 PC 파일에 적용하며, 기존 파일의 이번 반영 범위는 `기업/상품/U+MDR/` 하위 `pc.html`이다. 다른 상품의 기존 파일과 `mo.html`에는 소급 적용하지 않는다.
- MO는 상위 블록의 공통 스타일을 사용한다. `.cont-box-inner` 직계 콘텐츠 래퍼(`div` 또는 `section`)에 `width: 100%; min-width: 0; margin: 0; padding: 0 20px 88px; background: #fff; color: #181a1b; font-family: Pretendard, sans-serif;`를 묶은 중복 기본 CSS 블록을 생성하지 않는다. 기존의 해당 블록도 삭제한다.
- MO 직계 콘텐츠 래퍼에는 필요한 디자인별 CSS만 작성한다. 폭·바깥 여백을 명시할 때는 **`width: 100%; margin: 0;`**을 사용하며, `width: calc(100% - 40px);`와 `margin: 0 20px;`은 사용하지 않는다. 디자인 고유의 내부 `padding`·배경과 하위 요소 스타일은 유지한다.
- 앞으로 생성하는 `mo.html`에 적용하며, 기존 파일의 이번 반영 범위는 `기업/상품/U+MDR/` 하위 `mo.html`이다. 다른 상품의 기존 MO와 `pc.html`은 변경하지 않는다.
- 한 파일에 들어가는 모든 섹션은 하나의 최상위 래퍼 안에 순서대로 작성한다.
- 본문 밖에 별도 배너·sticky menu·CTA를 자동 삽입하지 않는다.
- CMS 삽입용 조각이므로 `<!DOCTYPE>`, `html`, `head`, `body` 태그를 넣지 않는다.
- 스타일과 본문을 섞지 않는다. 레이아웃은 style 블록에 작성한다.
- 정적인 파일에는 script를 넣지 않는다. 필요한 경우 HTML 영역 종료 후 `<!-- script -->`와 `<script>` 블록을 추가한다.
- 예시의 대괄호 문구와 주석은 실제 영역명으로 바꾼다. 설명용 빈 마크업을 결과물에 남기지 않는다.

## 4. Figma MCP 확인 순서

1. 지정된 링크에서 파일 키와 노드 ID를 확인한다.
2. 연결된 Figma MCP의 디자인 구현 지침을 읽고 `get_design_context`로 노드 구조·문구·수치를 확인한다.
3. 응답의 스크린샷 또는 `get_screenshot`으로 해당 PC/MO 화면을 직접 확인한다.
4. 큰 노드가 축약되어 반환되면 하위 섹션 노드를 확인한다. 불완전한 응답만으로 본문을 작성하지 않는다.
5. 디자인 노드 내부 에셋을 확인하고 준비된 로컬 파일과 대조한다. 필요한 에셋을 확인할 수 없을 때만 추가 위치나 링크를 요청한다. VAR-05의 전체 참고용 링크는 선택이며 기기별 디자인 링크를 대신하지 않는다.
6. 같은 출력 파일의 섹션 순서를 확정한 뒤 PC를 작성하고 MO는 MO 원본에 맞춰 별도로 작성한다.
7. 최종 코드를 각 원본 화면과 다시 대조한다.

- MCP가 반환한 React·Tailwind 등의 코드는 분석 자료다. 최종 결과는 이 가이드의 HTML·CSS·필요한 JavaScript 형식으로 작성한다.
- 디자인 텍스트를 그대로 옮긴다. 문구·요금·약정·단위·각주·강조 범위를 임의로 요약하거나 수정하지 않는다.
- PC/MO의 문구나 구성에 차이가 있으면 각각의 원본을 따른다. 의미상 충돌이 있으면 차이를 보고하고 임의 통일하지 않는다.
- 화면의 사진·아이콘은 에셋으로, 제목·설명·요금표는 가능한 한 실제 HTML로 구현한다. 화면 전체 스크린샷을 본문 대신 넣지 않는다.
- 기존 상품을 검색해 디자인이나 빠진 내용을 채우지 않는다.
- 탭형은 각 링크의 선택된 탭·패널 내용·공통 영역을 구분한다. 버튼이 각 패널 안에 있으면 각 패널에, 탭 밖 공통 영역에 있으면 그 위치에 구현한다. PC/MO 구조가 다르면 각각의 디자인을 따른다.

## 5. style 작성 기준

- **공통 고정 style은 없다.** 출력 폴더별·기기별 Figma 디자인에 맞게 CSS를 작성한다.
- 글꼴, 크기, 굵기, 행간, 자간, 색상, 여백, 모서리, 배경, 정렬을 노드 데이터에서 확인한다.
- **색상은 Figma 원본값을 그대로 사용한다.** #828282는 #828282로 출력한다. 웹접근성·명도 대비 개선을 이유로 #616161 등으로 임의 치환하지 않는다. 텍스트·강조·아이콘·배경·테두리 모두 적용하며, 색상 변경은 사용자의 별도 요청이 있을 때만 수행한다.
- 기존 파일의 폭·최소 폭·글자 크기·PC→MO 변환 비율을 강제하지 않는다.
- Figma의 자간 표기를 유효한 CSS 단위로 변환한다. 예를 들어 -2% 자간은 `letter-spacing: -0.02em`이며 CSS에 `-2%`를 그대로 쓰지 않는다.
- PC와 MO는 별도 파일로 작성한다. 하나의 반응형 파일로 합치지 않는다.
- 같은 역할의 요소는 가능하면 PC/MO에서 같은 의미의 클래스명을 사용하되, 구조가 다른 경우 MO 디자인에 맞게 변경한다.
- 클래스는 이번 상품·영역을 식별할 수 있게 작성한다. 본문 내부 섹션 클래스로 선택자 범위를 제한해 다른 탭과 충돌하지 않게 한다.
- `body`, `html`, 전역 `p`·`button` 등의 스타일로 CMS 전체 화면에 영향을 주지 않는다.
- 각 파일은 자신이 사용하는 콘텐츠 CSS를 자체 포함한다. 다른 탭의 style이 먼저 로드된다고 가정하지 않는다.
- 사이트 공통 CSS에 의존해야 하는 사항이 있으면 실제 제공된 규칙을 확인하고 보고한다. 확인되지 않은 전역 스타일을 가정하지 않는다.
- Figma 레이어의 절대 좌표를 모두 절대 위치로 옮기지 않는다. 일반 문서 흐름·flex·grid로 배치하고 겹치는 요소에만 필요한 위치 지정을 사용한다.
- 수치가 불명확하면 노드를 추가 확인한다. 이전 디자인의 값을 가져와 채우지 않는다.
- 제목 끝의 장식 dot은 `::after { content: ''; }`로 구현한다. 크기·색상·간격은 해당 PC/MO 디자인을 따르고 원형은 `border-radius: 50%`로 만든다. dot용 SVG·PNG는 만들지 않는다.

## 6. 에셋 확인·저장·경로

### 에셋 확보

- VAR-08에 준비된 파일이 있으면 실제 파일을 열어 Figma의 모양·색상·비율·사용 위치와 대조한다.
- 명령문에 기기별 파일명 규칙이 제공되면 그 규칙으로 후보를 구분한다. PC/MO 이미지가 한 폴더에 있으면 `pc/`, `mo/`를 경로에 추가하지 않는다. 숫자가 같아도 동일 용도의 에셋이라고 가정하지 않는다.
- 준비된 파일이 없으면 지정된 Figma 디자인 노드에서 원본 에셋을 MCP의 PNG 내보내기로 확보한다. 추가 에셋 노드를 제공받았다면 해당 디자인의 사용 위치와 대조한다.
- **Figma 다운로드 형식은 PNG(.png)로 통일한다.** PC/MO의 사진·이미지·아이콘 모두 적용하며 SVG 파일은 다운로드하지 않는다. 벡터 에셋도 원본 노드를 PNG로 내보내고, 확장자만 바꾸는 방식은 금지한다.
- MCP 응답에 SVG 임시 URL이 있어도 그대로 저장·연결하지 않는다. 해당 노드의 PNG 내보내기를 사용하고, PNG 확보가 불가능하면 그 항목만 간략히 보고한다.
- 사진·아이콘을 임의 생성하거나 다른 상품 이미지로 대체하지 않는다.
- 별도 `assets` 폴더는 만들지 않는다. 내보내는 에셋은 VAR-08이 있으면 그 폴더에, 없으면 `[VAR-00]/[VAR-03]/`에 저장한다. 두 저장 위치가 모두 미정이면 확인한다. `pc/`, `mo/` 하위 이미지 폴더도 자동으로 추가하지 않는다.
- 기존 에셋은 실제 파일명을 유지한다. 새로 내보내는 에셋은 확인한 노드 이름·ID로 구분되는 파일명을 정하고 결과에 기록한다. 파일명이나 순서만으로 사용 위치를 판단하지 않는다.
- PC와 MO가 같은 에셋을 사용하더라도 비율·크롭·배경 위치는 각 디자인을 확인한다.
- 에셋 링크의 다운로드에 실패하거나 파일이 비어 있으면 정상 확보로 기록하지 않는다.

### 경로 구성

- CDN 값이 확정되면 `[VAR-02][VAR-03]/[실제 에셋 상대경로]`를 사용한다. VAR-02는 이미지 폴더 바로 앞까지의 경로이며 끝에 `/`를 붙여 RMS 번호가 중복되지 않게 한다.
- `product/`, `pc/`, `mo/` 등의 경로는 실제 등록 구조를 따른다. 다른 상품의 CDN 경로를 가져오지 않는다.
- CDN 값이 미정이면 각 HTML 위치에서 실제 에셋 파일까지의 상대경로를 계산한다. 예: `1.상품개요/pc.html`에서 상품 루트의 `[VAR-03]/img_prod_1.png`는 `../[VAR-03]/img_prod_1.png`로 참조한다.
- Figma의 만료되는 임시 에셋 URL, 존재하지 않는 파일명, 빈 `src`를 결과에 넣지 않는다.
- CSS `url()` 경로는 따옴표로 감싸고 공백은 `%20`으로 처리한다. 링크·HTML 속성은 해당 문법에 맞게 이스케이프한다.
- 이미지 업로드는 작업자가 별도로 진행한다. 지정 CDN 경로로 HTML을 작성하되 업로드·응답 확인은 실행하지 않으며, CMS 등록 완료라고 보고하지 않는다.

### 이미지가 없을 때

- 확보할 수 없는 에셋만 누락 목록에 적는다. 파일명·내용을 추정하지 않는다.
- 사용자가 이미지 없이 진행하도록 지시했다면 해당 이미지를 생략하고 문구와 레이아웃 구조를 유지한다.
- 필요한 이미지 공간과 읽을 수 있는 배경은 유지하되, 임의 대체 그림·깨진 이미지·사용자 화면의 작업 안내 문구는 넣지 않는다.
- 보고에는 생략 위치와 그에 따른 시각적 차이를 명시한다. 이 예외를 다음 상품의 기본 설정으로 이어받지 않는다.

## 7. 링크와 상호작용

- 디자인에 존재하는 링크·버튼만 구현한다. VAR-01이나 태깅을 입력했다는 이유로 별도 하단 CTA를 만들지 않는다. 버튼이 없으면 버튼 관련 입력은 비워둔다.
- 상품보러가기·신청하기 구분 없이 VAR-01 하나에서 버튼 위치·문구·URL·동작을 관리한다. 입력 항목의 통합을 이유로 디자인에 있는 버튼을 임의로 삭제하거나 추가하지 않는다.
- 버튼의 위치·개수·배치·문구·스타일은 Figma를 따른다. VAR-01의 적용 위치가 비어 있어도 디자인에서 대상이 식별되면 구현한다. 화면 문구와 입력 문구가 다르면 차이를 보고한다.
- 같은 문구·URL·동작의 버튼이 여러 영역이나 탭에 있으면 모두 연결한다. 서로 다른 URL·동작은 VAR-01 내부의 버튼별 블록에서 그룹·탭·영역으로 구분한다. 매핑이 모호할 때만 확인한다.
- 탭 선택 버튼은 패널 전환 전용이다. VAR-01의 상담·이동 URL을 탭 선택 버튼에 붙이지 않는다. GTM은 별도 제공된 해당 버튼의 속성만 적용한다.
- 제공된 URL의 파라미터를 보존한다. 블로그의 `menuLocNm` 치환 규칙을 상품에 적용하지 않는다.
- 이동 링크는 `a`, 탭 전환·펼침 등 동작은 `button type="button"`을 사용한다.
- 팝업 크기·이름·스크롤 offset·sticky 위치를 이전 상품에서 복사하지 않는다. 요청된 동작에 맞게 구현한다.
- 내부 탭·펼침의 각 상태를 확인하고 해당 파일 안에 필요한 script를 포함한다. 접근성 속성·키보드 이동도 상태와 함께 갱신한다.
- script는 해당 콘텐츠 내부로 선택자 범위를 제한하고, 이벤트 중복 등록과 다른 탭에 대한 영향을 방지한다.
- 목적지나 상세 상태가 없으면 해당 누락을 보고하고 확정된 부분을 진행한다. 비활성화·생략 등의 처리 방향은 사용자 지시에 따르며 임의의 빈 화면을 정상 상태로 만들지 않는다.
- 정적인 파일에는 빈 script나 공통 함수 묶음을 넣지 않는다.

### 아코디언 구성 규칙

- 그룹은 `[data-cqm-accordion]`, 제어 버튼은 `button[data-cqm-accordion-trigger]`, 펼침 영역은 `[data-cqm-accordion-panel]`로 구분한다.
- 버튼에 `type="button"`, `aria-expanded`, `aria-controls`를 지정하고 대응 패널의 고유 ID와 연결한다. ID에는 상품·섹션·기기·그룹·항목을 구분할 수 있는 값을 사용한다.
- 초기 HTML의 `aria-expanded`와 패널 `hidden`을 일치시키고, 클릭 시 함께 갱신한다. Enter/Space는 기본 button 동작을 사용하고 키보드 초점을 표시한다. 접히는 패널 안에 초점이 있으면 먼저 제어 버튼으로 옮긴다.
- 여러 항목·그룹은 기본 독립 동작이다. '하나만 펼침'이 지정된 경우에만 해당 그룹의 다른 항목을 닫는다. 부모 그룹이 중첩 그룹이나 탭 상태를 변경하지 않도록 소속을 구분한다.
- 문서 이벤트 위임을 한 번 등록하여 CMS 지연 삽입·교체에 대응한다. 고정 딜레이에 의존하지 않으며, 탭과 아코디언은 서로 다른 선택자·전역 이름을 사용한다.
- 디자인에 있는 문구·화살표·상태 표현을 사용한다. 필요한 스크립트는 해당 PC/MO 파일의 HTML 뒤에 포함하고, 별도 파일·폴더를 늘리지 않는다. 동작 검증은 사용자 요청 시에만 수행한다.

### 공통 탭 구조와 스크립트 규약

탭의 선택·키보드 동작은 아래 공통 원본을 사용하고, CSS는 해당 디자인에 맞게 작성한다. 상품별로 바꾸는 것은 마크업의 그룹·탭 키·고유 ID·문구와 디자인 CSS다. 별도 JS 파일 없이 필요한 PC/MO 파일에 같은 스크립트를 한 번 포함한다.

| 역할         | 공통 선택자 / 속성                                    | 작성 기준                                                                                                                |
| ------------ | ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 그룹 루트    | `[data-cqm-tabs]`                                     | 값은 VAR-06의 그룹 ID. 한 그룹은 자기 탭 메뉴·패널만 제어한다.                                                           |
| 탭 메뉴      | `[data-cqm-tablist]`, `role="tablist"`                | 디자인의 그룹 제목을 `aria-labelledby`로 연결하거나 의미 있는 `aria-label` 지정. 방향은 `aria-orientation`으로 구분한다. |
| 탭 선택 버튼 | `button[data-cqm-tab]`, `type="button"`, `role="tab"` | 고유 `id`, 연결 패널의 `aria-controls`, `aria-selected`, `tabindex` 지정. data 값은 그룹 안에서 고유한 탭 키.            |
| 콘텐츠 패널  | `[data-cqm-panel]`, `role="tabpanel"`                 | 탭과 같은 data 키, 고유 `id`, 연결 탭의 `aria-labelledby`. 비활성 패널은 `hidden`.                                       |

- DOM ID는 상품 식별자·섹션 순서·기기·그룹 ID·탭 키를 조합한다. PC/MO 또는 여러 섹션이 같은 문서에 함께 들어가도 중복되지 않아야 한다. 동일 조각의 복수 삽입까지 필요하면 인스턴스 접두어를 추가한다.
- 구조를 JS 선택자로, 디자인 클래스는 스타일용으로 사용한다. 공통 동작이 특정 상품 클래스·탭명·배열 위치에 의존하지 않게 한다.
- 숨김 규칙은 각 파일 CSS에 `[data-cqm-tabs] [data-cqm-panel][hidden] { display: none !important; }`로 포함한다. 다른 탭 밖 요소에는 적용하지 않는다.
- 같은 섹션에 여러 그룹이 있거나 원본에 중첩 그룹이 있는 경우, `element.closest('[data-cqm-tabs]') === group`인 탭·패널·이벤트만 해당 그룹 소유로 처리한다. 부모 그룹은 자식 그룹의 선택 상태를 변경하지 않는다.
- 최초 HTML부터 그룹별 활성 탭 1개와 보이는 패널 1개를 지정한다. 입력된 초기 활성 탭을 우선하며, 미지정 시 Figma 기본 상태, 그것도 불명확하면 첫 번째 탭을 사용한다. 나머지 패널은 초기 HTML에서 숨긴다.

**공통 초기화·전환 절차**

1. 공통 진입점은 `window.CqmTabs.init(container)`로 정한다. `container` 자체와 그 내부의 그룹을 찾으며, 함수 정의는 전역 존재 여부를 확인해 한 번만 등록한다. 이미 다른 구현이 같은 이름을 사용하면 덮어쓰지 말고 호환성을 확인한다.
2. 그룹마다 탭과 패널의 키·ID·ARIA 연결을 검증한다. 문서에 클릭·키보드·초점 이탈 이벤트를 한 번만 위임하고, 조작할 때 해당 그룹의 현재 DOM을 조회한다. 본문 전체 또는 그룹 내부가 교체되어도 이벤트를 다시 등록하지 않는다.
3. 클릭은 해당 그룹의 탭 선택 버튼에만 반응한다. 비활성화된 탭은 선택하지 않는다. 활성 탭의 `aria-selected="true"`, 나머지는 `false`로 바꾸고 패널의 `hidden` 상태를 함께 갱신한다.
4. 키보드는 수동 활성화 방식으로 통일한다. 가로 탭은 좌우, 세로 탭은 상하 방향키로 초점을 이동하고 끝에서 순환한다. Home/End는 처음/마지막 사용 가능한 탭으로 이동하며 Enter/Space는 선택한다. 탭 순회 대상의 `tabindex`는 하나만 0, 나머지는 -1로 유지한다. 가로 탭의 상하 방향키 등 관계없는 키는 기본 스크롤 동작을 유지한다.
5. 탭 목록에서 초점이 나가면 다음 진입 대상은 선택된 탭이 되도록 roving tabindex를 정리한다. 패널의 첫 의미 있는 콘텐츠가 초점 가능하지 않으면 패널에 `tabindex="0"`을 두어 키보드 접근을 제공한다. 패널 전환만으로 다른 그룹·페이지 스크롤·상담 링크를 실행하지 않는다.
6. 그룹 내부의 탭 상태만 바꾸고 패널 DOM을 다시 만들지 않는다. 입력값·내부 하위 탭 상태를 보존하고 비활성 패널의 컨트롤은 키보드 탐색에서 제외한다. 모바일에서 가로로 넘치는 탭 메뉴는 디자인을 따르되 선택 탭이 보이도록 메뉴 내부 스크롤만 조절한다.
7. 공통 원본을 각 PC/MO 파일의 HTML 뒤 script에 한 번 포함한다. `init(document)`로 현재 그룹을 정리하고, 이후 삽입·교체된 그룹은 이벤트 위임으로 처리한다. `document.currentScript`, 스크립트의 형제 위치, 고정 지연 시간이나 DOM 감시자를 사용하지 않는다. `start`는 기존 호출 호환용 `init` 별칭이다.
8. 늦게 삽입할 HTML도 최초 상태부터 선택 탭·tabindex·hidden·ARIA 연결을 올바르게 작성한다. 초기 상태를 정리해야 하면 CMS 삽입 완료 시 연결된 DOM에 `CqmTabs.init(삽입한 컨테이너)`를 호출한다. `CqmTabs.init()`은 문서 전체를 대상으로 하며 기존 선택 탭은 유지한다. 실행되지 않는 script를 이벤트 위임이 대신 실행해 주는 것은 아니다.
9. CMS에서 스크립트가 최소 한 번 실행되어야 자동 초기화가 가능하다. script 제거·실행 차단·CSP 제한은 딜레이로 해결하지 않는다. 이 경우 CMS에서 허용하는 공통 스크립트 영역에 아래 원본을 등록해야 하며, 실제 CMS 확인 전에는 연동 완료로 보고하지 않는다.

키보드·ARIA 연결 기준은 [W3C APG Tabs Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)을 따른다. 색상·크기·활성 표시·버튼 배치는 공통 고정 CSS로 만들지 않고 각 Figma 디자인에 맞춘다.

### 공통 탭 스크립트 원본

- 아래 코드를 탭이 있는 파일의 HTML 뒤에 그대로 포함한다. 특정 상품명·CSS 클래스·고정 시간 값을 추가하지 않는다.
- `data-cqm-tabs` 그룹 안에는 역할·이름과 ARIA 연결을 갖춘 탭 메뉴 하나와 대응 패널을 작성한다. 숨김 CSS와 키보드 초점 표시는 각 파일 style에 포함한다.
- 같은 페이지에서 여러 상품·PC/MO·중첩 그룹이 함께 사용되어도 DOM ID는 문서 전체에서 고유해야 한다. 잘못된 연결은 콘솔에 보고하며 다른 패널에 임의로 연결하지 않는다.
- 이미 로드된 다른 버전의 `CqmTabs`는 덮어쓰지 않는다. 공통 코드를 교체할 때는 CMS에 적용한 복사본들을 함께 갱신하고 새로고침하여 검사한다.
- 스크립트 수정 시 원본과 적용 파일의 코드 일치를 확인한다. 일반 로드·분리 실행·지연 삽입·전체/그룹 내부 교체, 클릭·키보드·접근성 상태를 회귀 검사한다.

```html
<script>
  (function () {
    "use strict";
    var version = "2.0.0";
    if (window.CqmTabs) {
      if (window.CqmTabs.version === version) window.CqmTabs.init(document);
      else
        console.error(
          "CqmTabs: 공통 스크립트 버전을 통일한 뒤 새로고침하세요.",
        );
      return;
    }
    function read(group) {
      function own(selector) {
        return Array.from(group.querySelectorAll(selector)).filter(
          function (el) {
            return el.closest("[data-cqm-tabs]") === group;
          },
        );
      }
      var lists = own("[data-cqm-tablist]");
      var tabs = own("[data-cqm-tab]");
      var panels = own("[data-cqm-panel]");
      var keys = new Set(),
        ids = new Set();
      var valid =
        lists.length === 1 && tabs.length > 0 && tabs.length === panels.length;
      tabs.forEach(function (tab) {
        var key = tab.getAttribute("data-cqm-tab");
        var matches = panels.filter(function (p) {
          return p.getAttribute("data-cqm-panel") === key;
        });
        var panel = matches[0];
        if (
          !key ||
          keys.has(key) ||
          !lists[0] ||
          !lists[0].contains(tab) ||
          tab.tagName !== "BUTTON" ||
          tab.getAttribute("role") !== "tab" ||
          matches.length !== 1 ||
          !panel ||
          panel.getAttribute("role") !== "tabpanel" ||
          !tab.id ||
          !panel.id ||
          tab.id === panel.id ||
          ids.has(tab.id) ||
          ids.has(panel.id) ||
          tab.getAttribute("aria-controls") !== panel.id ||
          panel.getAttribute("aria-labelledby") !== tab.id ||
          document.getElementById(tab.id) !== tab ||
          document.getElementById(panel.id) !== panel
        )
          valid = false;
        keys.add(key);
        ids.add(tab.id);
        if (panel) ids.add(panel.id);
      });
      var enabled = tabs.filter(function (tab) {
        return !tab.disabled && tab.getAttribute("aria-disabled") !== "true";
      });
      if (!valid || !enabled.length) {
        console.error("CqmTabs: 탭 키·ID·ARIA 연결을 확인하세요.", group);
        return null;
      }
      return { list: lists[0], tabs: tabs, panels: panels, enabled: enabled };
    }
    function rove(ctx, tab) {
      ctx.tabs.forEach(function (item) {
        item.tabIndex = item === tab ? 0 : -1;
      });
    }
    function reveal(ctx, tab) {
      var a = ctx.list.getBoundingClientRect(),
        b = tab.getBoundingClientRect();
      if (b.left < a.left) ctx.list.scrollLeft += b.left - a.left;
      else if (b.right > a.right) ctx.list.scrollLeft += b.right - a.right;
    }
    function select(ctx, tab) {
      ctx.tabs.forEach(function (item) {
        item.setAttribute("aria-selected", String(item === tab));
      });
      ctx.panels.forEach(function (panel) {
        panel.hidden =
          panel.getAttribute("data-cqm-panel") !==
          tab.getAttribute("data-cqm-tab");
      });
      rove(ctx, tab);
    }
    function selected(ctx) {
      return (
        ctx.enabled.find(function (tab) {
          return tab.getAttribute("aria-selected") === "true";
        }) || ctx.enabled[0]
      );
    }
    function init(container) {
      container = container || document;
      var groups = Array.from(container.querySelectorAll("[data-cqm-tabs]"));
      if (container.matches && container.matches("[data-cqm-tabs]"))
        groups.unshift(container);
      groups.forEach(function (group) {
        var ctx = read(group);
        if (ctx) select(ctx, selected(ctx));
      });
    }
    function handle(event) {
      var tab = event.target.closest && event.target.closest("[data-cqm-tab]");
      var group = tab && tab.closest("[data-cqm-tabs]");
      if (!group) return;
      var ctx = read(group);
      if (!ctx || ctx.enabled.indexOf(tab) < 0) return;
      if (event.type === "focusout") {
        // 초점 이동이 끝난 뒤 선택 탭을 다음 Tab 진입점으로 복원한다.
        setTimeout(function () {
          if (!group.isConnected) return;
          var current = read(group);
          if (current && !current.list.contains(document.activeElement))
            rove(current, selected(current));
        }, 0);
        return;
      }
      if (event.type === "click") {
        select(ctx, tab);
        tab.focus({ preventScroll: true });
        reveal(ctx, tab);
        return;
      }
      if (event.altKey || event.ctrlKey || event.metaKey) return;
      var vertical = ctx.list.getAttribute("aria-orientation") === "vertical";
      var index = ctx.enabled.indexOf(tab),
        next;
      if (event.key === (vertical ? "ArrowDown" : "ArrowRight"))
        next = (index + 1) % ctx.enabled.length;
      else if (event.key === (vertical ? "ArrowUp" : "ArrowLeft"))
        next = (index + ctx.enabled.length - 1) % ctx.enabled.length;
      else if (event.key === "Home") next = 0;
      else if (event.key === "End") next = ctx.enabled.length - 1;
      else if (event.key === "Enter" || event.key === " ") {
        event.preventDefault();
        select(ctx, tab);
        reveal(ctx, tab);
        return;
      } else return;
      event.preventDefault();
      var target = ctx.enabled[next];
      rove(ctx, target);
      target.focus({ preventScroll: true });
      reveal(ctx, target);
    }
    // 이벤트 위임: CMS가 나중에 삽입·교체한 탭도 같은 핸들러로 처리한다.
    document.addEventListener("click", handle);
    document.addEventListener("keydown", handle);
    document.addEventListener("focusout", handle);
    window.CqmTabs = { version: version, init: init, start: init };
    init(document);
    if (document.readyState === "loading") {
      document.addEventListener(
        "DOMContentLoaded",
        function () {
          init(document);
        },
        { once: true },
      );
    }
  })();
</script>
```

### GTM 버튼 태깅

- Figma 디자인 기준으로 버튼을 구현한 뒤 VAR-07의 영역·버튼명과 실제 클릭 요소를 매핑한다.
- 제공된 `data-gtm-*` 속성은 실제 `<a>` 또는 `<button>`에 적용한다. 주변 래퍼나 내부 span에 대신 붙이거나 중복 적용하지 않는다.
- 같은 버튼명이 반복되어도 영역별 action·location 등은 해당 영역의 입력값을 유지한다. 적용 대상 PC/MO에 해당 버튼이 있으면 각각 반영한다.
- 확정된 속성명·값을 보존하고 HTML 문법상 필요한 이스케이프만 적용한다. 상품명·영역명·이벤트 값을 임의 생성하거나 샘플에서 자동 치환하지 않는다.
- 디자인에 없는 영역·버튼은 태깅 입력만으로 만들지 않는다. 대응 대상이 없거나 태깅 값이 누락된 경우 보고하고, 다른 버튼에 임의로 붙이지 않는다.
- 명령문의 U+SASE 예시는 작성 형식 참고용이다. VAR-07이 비어 있으면 예시를 적용하지 않는다.
- GTM 속성을 출력한 것과 실제 분석 이벤트 수집 검증은 구분한다. 별도 요청 없이 GTM 컨테이너·이벤트 전송 스크립트를 추가하지 않는다.

## 8. 접근성과 작성 절차

### 접근성

파일 생성·수정에는 아래 접근성 제작 기준을 적용한다. 9장의 검증·평가는 추후 사용자가 요청할 때만 수행한다. 기술 점검은 [WCAG 2.2 A·AA](https://www.w3.org/TR/WCAG22/)의 해당 항목과 WAI 작성 지침을 참고한다. 이 체크리스트만으로 전체 페이지의 표준 적합성이나 인증을 보증하지 않는다.

**이미지와 대체 텍스트**

- 모든 `<img>`에 `alt` 속성을 명시한다. 장식용이거나 인접 HTML이 같은 정보를 빠짐없이 전달하는 중복 이미지에는 정확히 `alt=""`를 사용한다. `alt` 생략, `alt=" "`, 파일명·‘이미지’ 같은 무의미한 값으로 대신하지 않는다.
- 정보성 이미지에는 실제 내용과 문맥을 확인한 짧고 의미 있는 alt를 작성한다. 사진이라는 이유만으로 장식 처리하지 않고, 이미지에만 있는 핵심 정보·문구·수치를 누락하지 않는다.
- 차트·절차·요금표처럼 복잡한 이미지는 짧은 식별용 alt와 인접한 HTML 상세 설명을 함께 제공한다. 표는 `table`, 목록은 `ul`·`ol`로 보존하고 필요하면 `aria-describedby`나 설명으로 이동하는 링크로 연결한다. 긴 표를 하나의 설명 문자열로 읽히게 하는 방식만으로 대체하지 않는다.
- **이 상품 가이드에서는 공통규칙의 ‘100자 초과 시 빈 alt’ 방식을 적용하지 않는다.** 글자 수가 아니라 의미와 본문의 중복 여부로 판단한다. 정보성 이미지를 `alt=""`로 숨긴 뒤 `aria-describedby`만 붙여 해결했다고 간주하지 않는다.
- 링크·버튼 안의 이미지가 유일한 이름이면 alt로 목적·동작을 제공한다. 같은 컨트롤 안의 텍스트가 이미 목적을 설명하면 아이콘은 `alt=""`로 두어 중복 낭독을 피한다. 컨트롤 자체에는 빈 이름이 남지 않아야 한다.
- 인라인 SVG에는 `alt` 대신 역할에 맞는 이름을 제공한다. 장식 SVG는 `aria-hidden="true" focusable="false"`, 정보성 SVG는 `role="img"`와 `aria-labelledby` 등으로 이름을 연결한다. CSS 배경에만 의미 있는 정보를 두지 않는다.
- `.sr-only`는 시각적으로만 숨기며 보조기술이 읽을 수 있어야 한다. 필요한 설명에 `hidden`, `display:none`, `aria-hidden="true"`를 적용하지 않는다. PC/MO 대체 텍스트는 각 이미지의 실제 정보에 맞춘다.

이미지 판단 기준: [WAI alt 결정 트리](https://www.w3.org/WAI/tutorials/images/decision-tree/), [기능성 이미지](https://www.w3.org/WAI/tutorials/images/functional/), [복잡한 이미지](https://www.w3.org/WAI/tutorials/images/complex/).

**탭·키보드·컨트롤**

- 탭은 7장의 공통 규약을 따른다. 그룹 이름, `tablist`·`tab`·`tabpanel` 역할, 고유 ID와 ARIA 연결, 선택 상태와 실제 표시 패널의 일치를 확인한다. 페이지 이동 메뉴에 탭 역할을 잘못 부여하지 않는다.
- Tab/Shift+Tab으로 탭 목록에 진입·이탈할 수 있어야 한다. 방향키는 초점만 이동하고 Enter/Space로 선택한다. 패널 내용으로 이어지는 순서, 목록 재진입, 비활성 탭, 여러 그룹·중첩 그룹을 확인한다.
- 선택 표시와 키보드 초점 표시를 구분한다. 초점 테두리를 대체 표시 없이 제거하지 않고, 고정 영역·스크롤·잘림에 초점이 가려지지 않게 한다. 양수 `tabindex`로 순서를 강제하거나 키보드 초점을 가두지 않는다.
- 비활성 패널은 `hidden` 등으로 보조기술과 키보드 탐색에서 함께 제외한다. `aria-hidden="true"`만으로 내부 링크·버튼의 초점 이동을 차단할 수 있다고 가정하지 않는다. 초점이 있는 콘텐츠를 숨겨야 하면 먼저 해당 제어 버튼 등 논리적인 위치로 초점을 옮긴다.
- 이동은 `a`, 동작은 `button type="button"`으로 구현하고, 화면에 보이는 문구를 포함하는 접근 가능한 이름을 제공한다. 아이콘만 있는 버튼도 목적을 알 수 있어야 한다. `title`만으로 이름을 제공하지 않는다.
- 새창 링크는 기존 `title="새창열림"`·`rel="noopener"`와 함께 링크 내부 텍스트 또는 `.sr-only`로 새창 안내를 제공해 title에만 의존하지 않는다. 펼침은 `aria-expanded`·연결 대상을 동기화한다. 모달이 있으면 진입·닫기·초점 복귀를 확인한다.

**구조·표·시각 표시**

- 제목 수준은 내용 구조에 맞추고 DOM 읽기 순서와 시각적 순서를 일치시킨다. CMS에 삽입할 조각의 상위 제목·페이지 언어·랜드마크는 통합 환경에서 확인하고, 확인하지 못한 페이지 수준 항목은 별도 미검증으로 남긴다.
- 표에는 `caption`과 적절한 `th`·`scope`를 제공한다. `rowgroup`·`colgroup`은 실제 행·열 그룹과 일치시킨다. 복잡한 다단 헤더는 필요에 따라 `id`·`headers`로 데이터 셀과 연결한다.
- 일반 텍스트 명도 대비는 4.5:1 이상, 큰 텍스트(18pt 이상 또는 굵은 14pt 이상)는 3:1 이상을 확인한다. 기능 식별에 필요한 UI 경계·상태 등 비텍스트 요소는 인접색과 3:1 이상을 확인하며 비활성·장식 등 적용 예외를 구분한다. 활성 탭·필수 정보는 색상만으로 구분하지 않는다.
- 글자 200% 확대와 320 CSS px 상당 너비의 재배치에서 정보·동작 손실을 확인한다. 의미상 2차원 배치가 필요한 표는 표 영역에 가로 스크롤을 허용하되 페이지 전체의 불필요한 가로 스크롤을 피한다. 스크롤 영역에 키보드 진입점과 이름을 필요에 따라 제공하고 키보드로도 끝까지 확인한다.
- Figma 색상은 접근성 기준과 충돌하더라도 원본값을 유지한다. 명도 대비 문제는 추후 사용자 요청에 따른 평가 결과에 기록하며, 별도 색상 변경 요청 없이 수정하지 않는다. 의미·키보드 동작 등 접근성 구현 기준은 유지하고, 원본 색상을 유지했다는 이유로 접근성 통과 처리하지 않는다.

시각 표시 참고: [텍스트 명도 대비](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [재배치와 표의 예외](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html).

### 작성 절차

1. 범위·입력값·기존 파일 존재 여부를 확인한다.
2. Figma 디자인·스크린샷·에셋을 확인한다.
3. 섹션 구성과 에셋 매핑을 정한다.
4. PC의 style과 HTML을 작성하고 MO 원본에 맞춰 MO를 작성한 뒤, 버튼별 링크·동작과 VAR-07의 확정 태깅을 반영한다.
5. 상호작용이 필요한 파일에만 script를 추가한다.
6. 작업 파일과 핵심 변경을 간략히 보고·기록한다. 문법·시각·접근성·동작 검증은 추후 사용자 요청 시 9장의 해당 절차로 수행한다.

- 긴 파일은 논리적 섹션 단위로 나누되, 작성한 본문이나 최상위 래퍼를 중복 삽입하지 않는다.
- 부분 저장을 사용하는 경우 자동 포맷팅의 태그 보정 여부를 확인한다. 설정 변경이 필요하면 원래 값을 기록하고 작업 후 복원한다.
- 완성된 파일 전체를 안전하게 기록할 수 있으면 그 방식을 사용한다. 특정 도구의 이름이나 청크 방식 자체를 필수 조건으로 삼지 않는다.
- 기존 문서·HTML·설정의 사용자 변경을 되돌리지 않는다.

## 9. 검증과 결과 보고

**아래 검증 표·평가 절차는 사용자가 검증을 요청했을 때만 적용한다.** 기본 생성·수정 작업에서는 검증을 실행하지 않고, 작업 기록에 '검증: 별도 요청 시 진행'으로 한 번만 적는다. 미검증 항목을 길게 나열하지 않는다.

실제 수행한 검증만 통과로 표시한다. 도구가 없거나 실행하지 못한 검증은 이유와 함께 미검증으로 적는다.

- Figma 원본 스크린샷 확인과 결과 HTML의 브라우저 렌더링 검증은 구분한다.

- 문서만 정리한 요청에서는 문서의 변수·상호 참조·규칙 일관성을 검토한다. HTML 제작용 검증이나 에셋 다운로드를 실행하지 않는다.

### 웹접근성 평가 절차 (사용자 요청 시에만 수행)

1. **평가 범위:** PC/MO 각 파일, 모든 탭 패널·펼침 상태·공통 버튼을 목록화한다. 숨겨진 패널도 실제로 활성화하여 평가한다. 입력 폼·영상 등이 있으면 그에 해당하는 레이블·오류 안내·자막 등 항목도 포함한다.
2. **정적/자동 검사:** HTML·ARIA 연결·ID·alt 누락·빈 컨트롤 이름·표 헤더를 확인한다. 사용 가능한 접근성 진단 도구로 각 상태를 검사하고 도구·버전·범위를 기록한다. alt가 있다는 사실만으로 내용이 적절하다고 판정하지 않는다.
3. **실제 브라우저 수동 평가:** 키보드만으로 진입·탭 전환·패널 탐색·링크·스크롤·이탈을 확인한다. 초점 표시·순서·트랩, 명도 대비, 확대·재배치도 검사한다. 실제 사용한 브라우저·화면 크기·확대 조건을 기록한다.
4. **스크린리더 평가:** 사용 가능한 스크린리더와 브라우저 조합에서 이미지 의미/장식 제외, 링크·버튼 이름, 탭의 이름·역할·선택 상태, 패널 연결, 숨김 패널 제외, 제목·표 읽기 순서를 확인한다. 제품명·버전과 확인한 상태를 기록한다.
5. **수정·재검사:** 발견한 문제의 파일·요소·재현 조건을 적고 범위 내에서 수정한다. 수정된 상태와 관련 전환을 다시 검사한다. 자동 검사 통과, 모의 DOM 테스트, 실제 키보드 조작, 스크린리더 낭독은 서로 대체한 것으로 기록하지 않는다.
6. **판정·보고:** 항목별로 `확인 범위 통과 / 이슈 있음 / 미검증 / 해당 없음`을 구분한다. 실행 제한·도구 부재·CMS 접근 불가 시 이유와 남은 평가를 명시한다. 미검증은 통과나 해당 없음으로 바꾸지 않으며, 남은 이슈가 있으면 ‘웹접근성 문제 없음’이라고 결론 내리지 않는다.

자동 검사만으로 접근성을 판정할 수 없으므로 수동 평가를 함께 수행한다. 참고: [WAI 접근성 평가 안내](https://www.w3.org/WAI/test-evaluate/). 실제 평가 환경이 준비되지 않았으면 구현 결과를 제공하되 접근성 평가 미완료로 보고한다.

검증 요청의 완료 보고에는 아래 항목을 파일별로 간략히 포함한다. 긴 점검 로그를 별도 파일로 만들지 않고 기존 작업 기록에 요약한다.

| 파일·평가 범위               | 환경/방법                          | 판정                       | 수정 사항·남은 이슈·미검증 이유 |
| ---------------------------- | ---------------------------------- | -------------------------- | ------------------------------- |
| 실제 파일과 확인한 패널/상태 | 실제 실행한 도구·브라우저·보조기술 | 위 4가지 판정 중 해당 결과 | 요소 위치와 핵심 결과만 기재    |

### 작업 기록 위치와 누적 방식

- 기록 파일은 명령문과 같은 위치의 [cqm\_작업내역.md](./cqm_작업내역.md), 즉 `기업/상품/cqm_작업내역.md` 하나만 사용한다. 없으면 생성한다.
- 상품 작업 폴더나 섹션 생성 폴더 안에 `작업결과.md` 등 별도 보고 파일을 만들지 않는다.
- 날짜와 실제 생성 폴더를 제목으로 구분한다. 여러 폴더를 작업하면 폴더별 항목을 작성한다.
- 기존 기록은 유지하고 새 작업 결과를 파일 맨 아래에 추가한다. 같은 폴더의 후속 수정도 새 항목으로 추가한다.
- 파일·핵심 변경·필수 전달 사항을 2~4개 항목으로 간략히 적는다. 이미지 업로드는 별도 진행 사항이며 반복 안내하지 않는다.
- 검증 요청이 없으면 '검증: 별도 요청 시 진행'만 적는다. 요청받아 검증한 경우에만 평가 범위·핵심 결과·남은 이슈를 짧게 추가한다.
- 전체 입력 변수, 긴 Figma URL·노드 목록, 상세 에셋 표, 검증 로그를 반복해서 기록하지 않는다. 실제 검증 범위와 미검증 사항은 구분한다.

### 간략 기록 형식

```text
## YYYY-MM-DD | 기업/상품/[상품 폴더]/[순서.이름]

- 파일: 생성·수정한 PC/MO 파일 링크.
- 작업: 주요 생성·수정 내용.
- 검증: 별도 요청 시 진행. (요청받아 수행한 경우에만 핵심 결과로 대체)
- 전달 사항: 작업 중 발견한 필수 사항만 기재. 없으면 생략.
```

상품별 작업 이력은 `cqm_작업내역.md`에만 누적한다. 이 가이드에는 제작 규칙만 유지한다.
